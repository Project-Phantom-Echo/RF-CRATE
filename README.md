# RF-CRATE: Towards White-Box Deep Wireless Sensing

**Xie Zhang** · University of Hong Kong, China  
**Yina Wang** · MIT, USA  
**Chenshu Wu** · University of Hong Kong, China

Published at [UbiComp / ISWC 2026](https://www.ubicomp.org/ubicomp-iswc-2026/).

RF-CRATE architecture

## Overview

RF-CRATE is an early step toward white-box deep wireless sensing grounded in
the complex sparse rate reduction principle. Using CR-Calculus, RF-CRATE
derives a fully complex-valued transformer with mathematically interpretable
self-attention and residual modules rather than relying on an ad-hoc
architecture.

Key findings from the paper include:

- **Subspace regularization (SSR):** a 19.98% average improvement by promoting
representation diversity under limited labeled data.
- **Complex-valued modeling:** a 3.39% gain in classification accuracy and a
10.34% reduction in regression error.
- **Broad evaluation:** heterogeneous RF modalities and human sensing tasks,
including activity, gait, and gesture recognition, pose estimation, and
respiration monitoring.
- **White-box analysis:** notebooks expose interpretable feature, attention,
and subspace structures in addition to reporting predictive performance.



## Abstract

The empirical success of deep learning has spurred its application to the
radio-frequency (RF) domain, leading to significant advances in Deep Wireless
Sensing (DWS). However, most existing DWS models remain black boxes, with
ad-hoc architectures and learned representations lacking explicit physical
and mathematical grounding, which limits their reliability and
generalizability in real-world deployments. We present RF-CRATE, an early step
toward white-box DWS grounded in the complex sparse rate reduction principle.
Using the CR-Calculus framework, we derive a fully complex-valued transformer
with mathematically interpretable self-attention and residual modules. To
address labeled data scarcity, we introduce subspace regularization to enhance
representation diversity, yielding a 19.98% average improvement. We evaluate
RF-CRATE across heterogeneous RF modalities and human sensing tasks, including
activity, gait, and gesture recognition, pose estimation, and respiration
monitoring. Experiments on five datasets show that RF-CRATE remains competitive
with strong black-box models while providing mathematically interpretable
architectures and representations. Moreover, the complex-valued design
achieves a 3.39% gain in classification accuracy and a 10.34% reduction in
regression error. Our results demonstrate that mathematically grounded models
can achieve strong performance in wireless human sensing, offering a promising
step toward more interpretable and physically grounded DWS systems.

## Repository Structure

```text
.
├── Configurations/             # Experiment YAML files
├── Datasets/                   # PyTorch dataset loaders
├── Models/                     # RF-CRATE and baseline models
├── Open_Datasets/              # Dataset-specific preparation instructions
├── logs/                       # Serialized paper-result records
├── runs/                       # TensorBoard runs
├── open_rfcrate_box_results/   # White-box analysis records
```

## Installation

Clone the repository:

```bash
git clone https://github.com/aiot-lab/RF-CRATE.git
cd RF-CRATE
```



### Conda environment

The environment is based on Python 3.8 (to ensure compatibility with CSIKit for loading Intel 5300 CSI .data files) and PyTorch 2.1:

```bash
conda env create -f environment.yml
conda activate rf_crate
```



### Lightweight installation

Alternatively:

```bash
conda create -n rf_crate python=3.8.18
conda activate rf_crate
pip install -r requirements.txt
```

To run the result notebooks, also install Jupyter and Seaborn if they are not
already available:

```bash
pip install jupyter seaborn
```

## Quick Start

Each experiment is defined by a YAML file under `Configurations/`. Pass its
**filename without** `.yaml`, not its path, to `--config_file`. The basename
must be unique within `Configurations/`.

For example,
`Configurations/widar3G6/widar3G6_rfcrate_small.yaml` is selected with
`--config_file widar3G6_rfcrate_small`.

### Train and test

After downloading and preparing the required dataset:

```bash
python main.py \
  --config_file widar3G6_rfcrate_small \
  --mode 0 \
  --cuda_index 0
```



### Pipeline check

Mode 3 runs a one-epoch check of the training and testing pipeline:

```bash
python main.py \
  --config_file widar3G6_rfcrate_small \
  --mode 3 \
  --cuda_index 0
```

Pretrained checkpoints are not distributed with this release. To reproduce an
experiment, prepare its dataset and run mode 0 with the corresponding
configuration. Checkpoints created by your own run can optionally be saved by
setting `model_save_enable: true`.

Depending on the YAML settings, an experiment writes:

- TensorBoard events to `tensorboard_folder` (normally `runs/<dataset>/`);
- test predictions and labels to `log_folder` when `log_enable: true`; and
- locally generated checkpoints to `trained_model_folder` when
`model_save_enable: true`.



## Experiment Configuration

The YAML files are the source of truth because values vary by dataset and
experiment. The most important shared fields are summarized below.

Experiment outputs and runtime


| Parameter              | Description                                                       |
| ---------------------- | ----------------------------------------------------------------- |
| `task`                 | Human-readable experiment name                                    |
| `init_rand_seed`       | Random seed used by PyTorch and NumPy                             |
| `cuda_index`           | CUDA device index                                                 |
| `tensorboard_folder`   | TensorBoard output directory                                      |
| `trained_model_folder` | Directory for checkpoints generated by local training             |
| `model_save_enable`    | Whether local training saves its best checkpoint                  |
| `log_folder`           | Test-result pickle directory                                      |
| `log_enable`           | Whether to save test predictions, labels, metrics, and attributes |


Training settings


| Parameter                        | Description                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------- |
| `num_epochs`                     | Maximum number of training epochs                                            |
| `early_stop`                     | Early-stopping patience                                                      |
| `batch_size`, `num_workers`      | Data-loading settings                                                        |
| `optimizer`                      | `AdamW`, `Adam`, `Lion`, or `SGD`                                            |
| `lr`, `weight_decay`, `momentum` | Optimizer hyperparameters                                                    |
| `criterion`                      | Task loss, such as `mse`, `cross_entropy`, `label_smoothing`, or `bone_loss` |
| `metric`                         | Evaluation metric, such as accuracy, F1, MPJPE, or MAE                       |
| `resume_training`                | Optional locally generated checkpoint filename, or `False`                   |


RF-CRATE model settings


| Parameter                     | Description                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `model_name`                  | Registered model variant                                                                                      |
| `model_input_shape`           | Input-layout convention expected by the model                                                                 |
| `num_classes`, `in_channels`  | Task output size and input channels                                                                           |
| `image_size`, `patch_size`    | Input and patch dimensions                                                                                    |
| `feedforward`                 | RF-CRATE feed-forward module type                                                                             |
| `relu_type`                   | Complex activation: `crelu`, `zrelu`, `modrelu`, or `cardioid`                                                |
| `patch_embedding_method`      | `linear_patch`, `conv_patch`, or `soft_conv_patch`                                                            |
| `mlp_head_type`               | `crate_version` or `vit_version`                                                                              |
| `output_type`                 | Complex-to-real output conversion, including `magnitude`, `real_imag`, `real`, or `phase_amp` where supported |
| `ssr`, `ssr_lambda`           | Enable SSR and set its loss weight                                                                            |
| `normalize_feature_magnitude` | Optional feature-magnitude normalization for SSR                                                              |
| `ppe`                         | Physics-prior embedding name, or `None`                                                                       |


Dataset-specific fields and split definitions are documented in the
corresponding YAML and `Open_Datasets/<dataset>/README.*` file.

### Result naming convention

`main.py` creates a shared experiment stem:

```text
<config_file>_<model_name>_<MMDDHHMMSS>
```

For a mapped experiment:

```text
Configuration: Configurations/<group>/<config_file>.yaml
Result:        logs/<group>/<experiment_stem>.pkl
TensorBoard:   runs/<group>/<experiment_stem>/
```

Cross-domain experiments may additionally produce
`<experiment_stem>_indomain_test.pkl`. It uses the same configuration and
TensorBoard run as the base result.

## White-Box Result Extraction

`open_rfcrate.py` extracts inputs, labels, attributes, features, QKV values,
and attention tensors for the white-box analysis notebooks. It requires a
locally trained model. Configure the YAML, local model path, and output path in
the script, then run:

```bash
python open_rfcrate.py
```

The released `open_rfcrate_box_results/` archive is sufficient to rerun the
corresponding paper notebooks without regenerating these records.
